lightcast @VERSION@ for Linux (x86-64) - how to install and run
========================================================================

This is a single static binary: it runs on any x86-64 Linux distribution
(glibc or musl, old or new) with nothing else installed. Linux has no
signing gate, so there is nothing to unblock, but do check the download
first. It does not need root; run it as your normal user, because it
scans the home directory of the user who runs it.

You need: lightcast-@VERSION@-x86_64-unknown-linux-musl.tar.gz and
SHA256SUMS, from the same release folder.


1. Check the download is intact
------------------------------------------------------------------------
    sha256sum --check --ignore-missing SHA256SUMS

The line for the .tar.gz must say OK. If it says FAILED, delete the
download and get it again. Do not run it.


2. Unpack and run
------------------------------------------------------------------------
    tar -xzf lightcast-@VERSION@-x86_64-unknown-linux-musl.tar.gz
    cd lightcast-@VERSION@-x86_64-unknown-linux-musl
    ./lightcast

Useful options:

    ./lightcast --html report.html     self-contained HTML report
    ./lightcast --json report.json     full report as JSON
    ./lightcast --verbose              every finding with evidence
    ./lightcast --help                 all options

Optional, to run it from anywhere:

    install -m 0755 lightcast ~/.local/bin/


If it does not run
------------------------------------------------------------------------
"Permission denied":
    chmod +x lightcast
    If it still fails, the folder may be on a filesystem mounted
    "noexec" (common for /tmp); move it to your home directory.

"cannot execute binary file: Exec format error":
    The machine is not x86-64 (for example a Raspberry Pi or another
    ARM machine). This release has no ARM Linux build yet.


About the report
------------------------------------------------------------------------
- It runs locally and sends nothing anywhere (see PRIVACY.md). The only
  exception is --resolve, which you must ask for.
- Exit code 1 means a finding at or above --fail-on (default: critical)
  was found. It is not a crash; use it in scripts and CI.

Signature files (*.sigstore.json) in this release are made with a test
key: they prove the release pipeline works, not who published it. See
TEST-SIGNED-READ-ME.txt if present.
